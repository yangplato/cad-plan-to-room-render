# 用户引导与逐步确认

面向用户的路径固定为 **01 原始资料 → 02 整理平面 → 03 彩平 → 04 空间效果图**。每一步先完成可审阅的成果和自检，再让用户确认当前版本，确认后引导下一步。内部可用A=01/02、B=03、C=04称谓；界面始终优先用四步编号，避免两套名字造成混淆。

## 第一次接触：按实际输入回应

| 用户情况 | 当下行动 | 第一次回应应包含 |
|---|---|---|
| 只@Skill，没有资料 | 简述用途与四步，不启动生图 | “我能把住宅平面整理成干净底图，再做指定风格彩平和各房间效果图。每一步先给你确认。你现在有CAD、平面图片，还是想先了解制作方式？” |
| 仅问功能/费用/能力 | 回答具体问题，说明实际可做范围；费用只按当前平台可见信息回答 | 给一个开始方式即可，不强迫上传、不制造任务或假定已授权整套制作 |
| 上传CAD | 直接检查文件是否可读、同图是否多方案、单位/外参、关键信息 | “我先确认你要用的这一套平面，并检查墙门窗和家具。随后给你一张识别预览，确认后再清理。”工具能读取就先做，不能读取则明确需要导出的PNG/PDF或DXF |
| 上传图片/PDF | 看完整性、清晰度、朝向、多页/多图、是否已有布置 | “我先检查这张图是否完整、家具和门窗能否辨认，再把不确定的位置标出来让你确认。”无比例也可做视觉方案，不能假报毫米精度 |
| 已有整理平面/彩平，要求后续 | 识别它的角色及版本，尽量承接，不机械重画 | 用户明确认可的现有图可作为对应上游确认；核对布局依据和风格归属，缺什么就只问什么 |
| 同时发多张不同用途的图 | 先区分布局、风格、质感、已选方案 | 实际内容明确的由Agent先分类；无法分辨且会影响制作的只问最关键一项，不笼统要求用户重讲全部 |

本轮只收集当前阶段所需内容，不在上传CAD时一次问完材质、镜头、十种风格和所有设备型号。识别技术、JSON、模型能力映射由Agent处理，不让客户填写技术配置。

## 四个成果确认点

### 01 原始资料识别

成果：目标方案的可见预览＋简短识别摘要，必要时标出少量疑点；不是只回复“文件已收到”。摘要说清选的是哪套平面、房间功能与关键家具/洁具、哪些信息看不清。多方案先让用户选目标，再完成该目标的识别。

展示后问：“这是我识别的这套方案，标出的〔具体位置〕是否正确？确认后我会整理成无标注底图。”只有实际存在的疑点才问；无疑点则请确认目标方案即可。若关键疑点未解，不把猜测画进下一步。

### 02 整理平面

成果：完整干净平面，最好与原图同朝向对照；附不超过几条主要整理说明，例如去掉尺寸、统一墙体剖面、澄清挂衣柜与洗衣机顶视。先自查建筑、开口、主要物件和通道，再交用户看布局是否准确。**未实际生成图像时不得展示文字清单冒充底图成果。**

提问示例：“请确认这张整理平面的布局与物件表达。若正确，下一步做彩平；你希望哪种风格？”可以同一轮收风格选择，但在布局被确认前不得执行03。先提供用户已提及的风格；没有偏好时简述2–3个相关方向，提供完整十风格选项供展开，不替用户默默选择。

### 03 彩平与设计选型

成果：实际彩平，标明底图版本与风格；附一句本套家具/地墙方向和已做的核验。不把“挂了参考图”当作质感达标。多风格按套分组，各自确认，不把认可其中一张扩大为全部。

提问示例：“这是〔风格〕彩平，是否确认这套家具、材料与质感？确认后，你希望先看客厅、餐厅还是卧室？”房间选择可提前记录，彩平仍需被确认后才能延伸。用户只说“喜欢这个风格”可能是风格方向认可，不等于确认当前图的布局与家具；结合明确指代判断，实质含糊才追问。

### 04 空间效果图

成果：本套彩平＋指定房间主图，附关键机位/可见关系的简短说明，以及需要用户决定的具体问题。先逐张自检，再请用户确认当前房间/批次。多房间授权可先完成一个代表主视角供确认，以此延续设计；已有明确批量委托则按其批次交付。

提问示例：“这张〔房间〕已对照平面核对，家具和材料沿用刚确认的彩平。构图和设计表达是否通过？通过后可沿用这一套制作〔余下房间〕。”若用户已要求全部指定房间，记住清单，不反复问房间名；按已同意的批次继续。

## 确认的含义

- 自检通过与用户确认是两个不同字段。确认绑定当前图/版本及具体风格或房间；用清楚指代的“这张可以，继续”可以确认，不强求用户输入哈希或固定口令。
- “做全流程”“直接开始”授权开展制作，默认不取消四步成果确认。用户明确说“中间不用等我／你代我确认”时记录其范围并依此继续，状态标为用户委托自检，不伪造逐图人工确认。真实冲突和超出委托的设计问题仍需处理。
- 询问后暂停依赖该确认的下一阶段，沉默、超时、预选选项、模型自评均不算用户确认。可以同时继续不依赖该决定的准备工作。
- 用户明确提供“已确认底图/彩平”可作为外部确认来源，不要求重复制作或重复同一个审批；仍检查文件能读、角色及版本一致。
- 用户要求改一处时，在当前阶段修正并重新展示，不急着进入后续。上游修改导致下游需复核，范围见下文。

## 修改、回退和续接

保存一份轻量状态即可：阶段、成果ID/版本、依赖版本、自检、用户反馈/确认、下一步。可以是文件，也可以是聊天摘要；格式见 [运行记录](run-record.md)，宿主接口见 [适配契约](adapter-contract.md)。

- 换CAD/墙门/主要布局：01和02回查，相关03/04标记需重做或复核，不继续说通过。
- 只改某风格家具/材料：更新该03设计版本，相关04失效；其他已确认风格不必重做。
- 只改一个镜头的构图或摆件：更新该04图及依赖它的后续视角，不重启全部平面。
- 中断恢复：先用一句话说明“目前停在02第2版待确认”，展示这版成果再续接；用户不用重新填需求表。
- 自检发现错误先自行处理。关键方案错误不交客户当成果确认；反复失败时展示具体失败位置与可行下一步，不用更多空泛Prompt无限重试。

正常阶段交付只需 **成果预览＋简短变化/检查＋一个明确的下一步问题**。不要让用户阅读适配器、日志、资产清单才能知道该做什么。
