# 每次运行的最小记录

确认和反馈保留在对话中，不另建确认文件。制作与续接需要的状态可合并进已有案例记录；没有读到、计算过或看过的内容写“未核实”。以下是信息项，不要求把模板全部扩成文件。

```text
案例/版本：
输入：原件名称；目标方案；实际可读文件；原生CAD时的单位/坐标变换/源文件哈希。
能力：看图／CAD解析／执行代码／携图生图／看生成图，各自实际可用情况。
A 房间信息：房间编号与名称；房间中的物品及必要布置；已确认事实和关键疑点；整理图版本及核对结果。
B 共同场景与本风格选型：主要家具特征、柜体外观与地墙材料；必须保留的用户指定条件；Agent设计引导及可自由完善的细部。
B补充：源图未锁定活动家具的设计调整及理由；方案确定依据；场景版本；全部相关主要物件的实际数量、位置、朝向、组合、尺寸依据与主要款式（含主图未入镜物件）；主图补全回写内容；修改后受影响视角。
C 镜头与约束图：用户选择的广角/近景或组合及确认来源；房间、机位、朝向、洞口/邻室、遮挡、光源；对应空间约束图的实际文件、依据版本、核对与传图状态；合理补全。
提示词确认：完整展开文本、实际输入图、对应风格/房间/机位、用户确认或明确委托。
每次生成：阶段/风格/房间；实际输入顺序与角色，所选参考的理由、借鉴/排除项或未附图的原因；完整实际Prompt；工具/模型（仅记录已知值）；输出文件；后续编辑。
效果图检查：依次记录空间与功能、主要物件合理性、同方案一致性、视觉表现；可供方案评判／需修正；只写影响空间理解、使用、风格或完整性的具体问题；合理细部差异不当成返工清单。
必要修正：最早错误步骤、影响什么判断、修复哪一步、更新哪些输入、同方案同机位累计轮数（上游修复后的重生成也计入）；停止原因与保留版本。
状态：生成未检／自检通过待用户审阅／用户接受／失败过程。
```

保存实际发送的 Prompt，不以更新后的通用模板覆盖历史请求。保留原始生成结果与局部修图的区别；有可用的文件系统时将失败尝试集中在过程目录。无文件工具时以消息交付同一份记录和图片，不假装写盘。

在对话中先展示底图，再按风格分组展示彩平和请求的房间效果图，附实际输入、完整 Prompt 和当前问题。不另建审阅页，不把检查日志堆到画面上。

## 最小续接状态

```text
当前阶段：01-source / 02-clean-plan / 03-color-plan / 04-room-render
成果：artifact_id、revision、可打开的实际文件或附件；父成果ID/版本。
自检：按当前阶段记录检查状态；04使用“可供方案评判／需修正”，01–03沿用各自阶段标准。04记录必须保留条件、必要问题和停止原因，不扩大不可见部位的精确核验。
用户确认：待确认／用户接受／用户要求修改／明确委托自检；原话及对应版本/风格/房间。
修改影响：哪些下游待复核；不能把旧版本确认复制到新版本。
下一步：展示哪张图、等待哪一项确认、确认后执行什么。
```

正常对用户只展示成果和一个清楚问题。内部状态不要求用户填写。确认绑定规则和修改失效范围以 [用户引导](user-journey.md) 为准。平台 Agent 在对话中接收确认；已有制作记录可保存续接状态，但不能要求用户到文件或独立界面确认。
