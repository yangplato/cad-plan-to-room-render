# 每次运行的最小记录

一份案例记录足够，按阶段填写已有信息；没有读到、计算过或看过的内容写“未核实”。不把模板全部扩成文件。

```text
案例/版本：
输入：原件名称；目标方案；实际可读文件；原生CAD时的单位/坐标变换/源文件哈希。
能力：看图／CAD解析／执行代码／携图生图／看生成图，各自实际可用情况。
A 本图确认信息：已确认墙门与连通、主要物件及朝向；关键疑点和依据；整理图版本及核对结果。
B 本风格选型：沙发/单椅/桌椅/床/柜门的具体构造；各房间地墙材料；保留的指定设计。
C 视角卡：房间、机位、朝向、景别、洞口/邻室、遮挡、光源；合理补全。
每次生成：阶段/风格/房间；实际输入顺序与角色；完整实际Prompt；工具/模型（仅记录已知值）；输出文件；后续编辑。
逐张检查：布局／使用合理性／摄影与材质；通过、未核实或具体问题；修正结果。
状态：生成未检／自检通过待用户审阅／用户接受／失败过程。
```

保存实际发送的 Prompt，不以更新后的通用模板覆盖历史请求。保留原始生成结果与局部修图的区别；有可用的文件系统时将失败尝试集中在过程目录。无文件工具时以消息交付同一份记录和图片，不假装写盘。

统一审阅按风格成组：一张彩平＋请求的房间效果图，每张附可展开的实际 Prompt/输入；底图放页首。不要把检查日志堆到画面上，也不要让用户在很多目录间跳转。
